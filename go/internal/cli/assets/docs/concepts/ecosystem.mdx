Wendy provides tools to build and operate AI applications on robots and edge
devices. Start with the part that matches your task. The products have separate
setup requirements and release status; using one does not automatically
configure the others.

## Understand the boundaries

For local development, the CLI talks to Wendy Agent on your device. Linux
targets run containers; supported Mac targets run native applications. Wendy
Lite uses a separate firmware workflow. You can deploy locally without Cloud
enrollment. Initial tool, image, and model downloads can still require internet
access.

For remote operation, Cloud adds device identities, organizational access, and
remote connections. Cloud v2 and v1 use separate enrollments, and v2 tunnels to
application ports need updated Cloud, CLI, and Agent versions. Use the
[migration guide](/docs/cloud-migration) before moving an existing fleet.

Wendy Data records episodes on the device. Upload is a
separate configuration, and BI needs its own access and data connection. Recording
an episode or enrolling a device does not automatically create a BI dashboard,
configure historical backtesting, or train a model.

To alert an operator, your application can request a notification through the
Agent. Cloud authorizes and stores it, and Companion provides the operator's
inbox and push experience. App registration, grants, recipient access, and a
compatible mobile build are required.

## Build a workflow in stages

Start with a locally running app and verify its output. Add Cloud access when
you need to operate remotely. Use Data to record a meaningful event and inspect
the resulting episode. Connect the data source required by your BI use case,
then verify its query result. Configure notifications separately when someone
needs to respond to an event.

Each stage should produce a result you can check. For example, deploying a
campaign arms it; the episode manifest confirms what actually recorded. Cloud
accepting a notification does not guarantee a phone received the push.

## Availability and security

Use the [roadmap](/docs/advanced/roadmap) for release status and each setup guide
for target-specific limits. Companion's App Store release and the reusable SDK
have separate release tracks. A simulated robot does not establish that a
policy is ready for physical hardware.

WendyOS, the CLI, and Wendy Agent are open source. Check the relevant product's
terms and deployment options for hosted services. Local operation, local model
inference, Cloud storage, and hosted AI calls have different network and data
requirements. See [Security](/docs/security) for implemented controls and work
still in progress.
