## Your development machine and your target

<Figure src="/images/get-started/jetson-usb-c.webp" alt="Overhead view of a laptop connected to an NVIDIA Jetson Orin Nano developer kit by one USB-C cable" caption="A development machine and a target: a laptop and a Jetson Orin Nano joined by one USB-C cable." />

The CLI runs on your development machine. A target is the machine that runs your app. WendyOS includes Wendy Agent; existing Linux and supported Mac machines can run the agent without replacing their OS. A simulator is a local VM running WendyOS.

`wendy run` selects a target, detects the project, builds for that target, uploads the result, starts the app, and attaches logs. Use `wendy run --watch` to repeat that loop when source files change.

Linux targets run containers. Mac targets run native macOS apps. ESP32 uses Wendy Lite and has a separate native firmware workflow.

Keep existing Dockerfiles, Compose projects, and standard ROS 2 application interfaces. A Stagefile is an optional build recipe. Deployment settings select resources and connectivity; they do not require rewriting your app.

## App configuration

[`wendy.json`](/docs/reference/app-configuration) names your app, chooses its platform, and declares the capabilities it needs. Entitlements grant access to hardware and other resources. A simulator can exercise the software deployment path. Physical hardware access is limited to opt-in [serial passthrough](/docs/installation/simulator-management#serial-passthrough); other peripherals need a real device.

## Optional cloud management

You can develop locally without enrolling in Wendy Cloud. The [Cloud guide](/docs/cloud)
covers Cloud v2 setup and a Legacy tab for existing v1 devices. Signing into v2
does not migrate those devices; follow [Moving to Cloud v2](/docs/cloud-migration)
before changing enrollment.

For Data, BI, Companion, SensorLink, and the other products, see
[The Wendy ecosystem](/docs/concepts/ecosystem).
