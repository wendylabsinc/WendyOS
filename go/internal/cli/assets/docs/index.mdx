Choose where your app will run. The simulator runs a real WendyOS ARM64 image on your laptop, so you can start without hardware.

<Tabs items={['Simulator', 'Jetson / Raspberry Pi', 'Existing Linux', 'Mac']}>
<Tab value="Simulator">

Use the quickstart below on macOS or Linux. Allow extra time for the first image download and build. Apple Silicon runs the ARM64 simulator natively; x86 hosts use slower emulation.

</Tab>
<Tab value="Jetson / Raspberry Pi">

First install WendyOS on your [Jetson](/docs/installation/wendyos-nvidia-jetson-orin-nano) or [Raspberry Pi](/docs/installation/wendyos-raspberry-pi-5). Connect it over USB or your local network, then follow the quickstart below and select it in `wendy run`.

</Tab>
<Tab value="Existing Linux">

On the **target Linux machine**, install the agent:

```bash
curl -fsSL https://install.wendy.dev/agent.sh | bash
```

Return to your development machine and follow the quickstart below. Select your Linux machine in `wendy run`. See [Linux setup](/docs/installation/linux) for requirements and connection help.

</Tab>
<Tab value="Mac">

To run a Linux app on your Mac, use the Simulator path. To deploy a native macOS app, follow [your first native Mac app](/docs/get-started/mac). Native Mac targets require Apple Silicon and macOS 15 or later, plus a Mac development machine.

</Tab>
</Tabs>

## 1. Install Wendy

On your development machine:

```bash
curl -fsSL https://install.wendy.dev/cli.sh | bash
wendy --version
```

This example builds a container image. Have Docker running with Buildx available, or use the [Apple Container builder](/docs/advanced/clients/wendy-cli/commands/run#image-build-args). You do not need Node.js locally to build the generated Dockerfile.

For the simulator, install QEMU:

<Tabs items={['macOS', 'Debian / Ubuntu']}>
<Tab value="macOS">

```bash
brew install qemu
```

</Tab>
<Tab value="Debian / Ubuntu">

```bash
sudo apt install qemu-system-arm qemu-efi-aarch64
```

</Tab>
</Tabs>

Using Windows with a physical target? Follow [developer machine setup](/docs/installation/developer-machine-setup) to install the CLI, then continue at step 2.

## 2. Create an app

```bash
wendy init hello-wendy --target wendyos --language node --template simple-api --var APP_ID=hello-wendy --var PORT=3000 --assistant skip --git-init no
cd hello-wendy
```

## 3. Run it

```bash
wendy run
```

Select the **Simulator** tab, press **c** to create a simulator, then select it and press Enter. Wendy downloads and boots the image on first use. If you already have a target, select that instead.

If you have a saved default device, Wendy uses it without showing the picker. To explicitly use a simulator:

```bash
wendy vm create hello-sim --profile generic
wendy run --device vm:hello-sim
```

Wendy builds the app, uploads it, starts it, and attaches its logs. After the server is ready, look for this line. This example is for the simulator; physical targets show their own address:

```text
App reachable at http://127.0.0.1:3000
```

Open the printed URL. You should see:

```json
{"message":"hello-world"}
```

<Callout type="info" title="Your first Wendy app is running">
That response came from the app on your target. Edit `src/index.ts`, then run `wendy run` again to deploy the change. Use `wendy run --watch` to rebuild and deploy as you edit.
</Callout>

If the target does not appear or the URL does not load, use [quickstart troubleshooting](/docs/errors). The simulator has no physical camera, GPU, GPIO, or USB devices; use hardware for those examples.

## Wendy in 60 seconds

```text
YOUR DEVELOPMENT MACHINE
  Wendy CLI / editor
          |
          | build, run, debug
          v
YOUR TARGET
  WendyOS, or an existing machine with Wendy Agent
    Your app
    Camera / GPU / GPIO / ROS 2
          |
          | optional enrollment
          v
  Wendy Cloud: fleet management and remote deployment
```

| Name | What it does |
| --- | --- |
| Wendy CLI | The `wendy` tool on your development machine. |
| WendyOS | Wendy's Linux OS for supported hardware and the simulator. It includes the agent. |
| Wendy Agent | Runs on the target and manages your apps. Install it on an existing Linux or supported Mac machine. |
| Wendy Cloud | Optional remote access and fleet management. |
| `wendy.json` | Your app's configuration, including its target platform and hardware permissions. |

[How Wendy works](/docs/concepts) explains the deployment model in more detail.
